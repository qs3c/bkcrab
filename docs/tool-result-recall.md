# 工具结果回溯

`recall_tool_result` 直接查询数据库 `session_messages` 中已有的工具消息。
上下文压缩只修改模型的工作集，不再生成文件存档，也不复制工具原文到另一张表。

## 读取方式

压缩后的工具摘要携带 `msg_ref`，值是原始消息在当前会话内的 `seq`。

```json
{"ref":41}
```

不传 `ref` 可列出可回溯的工具消息；`tool` 可按工具名筛选列表。
读取时可用 `grep` 做不区分大小写的子串搜索，并保留命中行上下各两行。

```json
{"ref":41,"grep":"failed","limit":1000}
```

普通读取和 grep 都支持 `offset` / `limit` 字符分页，默认 8,000 字符，
每页最多 32,000 字符。grep 的偏移量针对带行号的过滤结果。
截断时返回 `next_offset` 及完整的续读参数，继续读取时保持相同的 grep 条件。
列表最多显示最近 60 条；grep 最多选择前 40 个命中行。

## 引用与权限

- 用户、agent 和会话由当前回合注入，模型只能提供会话内的消息编号。
- 只读取 `role='tool'` 的行。非拥有者额外限定为自己的发言人身份。
- 同一个工具调用 ID 对应多条记录时，核对工具名及原文内容以确定编号；
  无法唯一确定或查询失败时，摘要不发布错误引用。
- 无持久化会话数据库的部署中，回溯工具返回不可用，压缩仍可正常进行。

## 删除的旧机制

- 压缩时写入 `memory/logs/history_*.jsonl` 的逻辑及其工作区路径参数。
- 基于上述日志搜索的 `memory_search` 工具。
- `retrieve_compacted_tool_result` 工具及 `context_archives` 的读写接口、记录类型和建表代码。
- `/insights` 的文件存档统计，改为当前会话数据库工具消息的数量与最近活动统计。

旧工具不再作为兼容入口保留。已有部署中的历史文件或旧表不参与运行；
本次代码变更不自动物理删除这些存量数据。
