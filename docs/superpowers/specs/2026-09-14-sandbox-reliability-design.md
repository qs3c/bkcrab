# 单机 Docker 沙箱可靠性

用户已批准继续 Compose，优先资源准入、工作区同步和故障恢复；不引入 Kubernetes 或双网关。

## 资源准入

部署环境设置每容器 CPU、内存、PID 上限，全局及每用户存活沙箱上限、有限等待时间。额度在创建前预留，创建失败归还；等待支持取消。用户身份跨延迟创建保留。执行中的沙箱不得空闲回收，空闲计时从工具完成后开始。未知用户归入同一 system 桶，不能按 agent 绕开用户限制。

## 工作区同步

Docker 使用逐文件流式上传，不再将整个仓库装入 map。同步包含 .git；跳过符号链接和特殊文件。采用有界内容比较，正确处理同大小修改；同步失败保留本地数据并记录错误。每次 Docker 工具写入/执行后同步和回收前同步，关闭时尽力同步。已有本地文件不被旧 MinIO 副本覆盖。项目作用域维持项目根路径语义。

磁盘硬配额由宿主机文件系统提供。已恢复 Tailscale 并确认服务器为 ext4、约 20 GiB 内存、16 逻辑 CPU。使用新建的 40 GiB 工作区文件系统启用 project quota，每用户 10 GiB/100000 inode；DinD 独立文件系统 20 GiB。保留原数据卷，复制迁移；不格式化根分区或原数据卷。沙箱 seccomp 阻止修改项目 ID/继承标记，DinD INPUT 防火墙禁止内部沙箱访问管理端口。

## 故障恢复

保留 unless-stopped，增加单机 host systemd timer 巡检脚本，只按 /livez 的连续失败重启网关，/readyz 失败只告警。设置启动宽限、冷却和最大重启次数。脚本精确定位当前 Compose 项目，不重启数据库或 DinD。提供日志轮转和备份/恢复操作说明，不把重启等同在途 agent 任务断点恢复。

## 验收

并发准入上限、用户跨 agent 限额、排队取消、创建失败释放、长命令不回收；大文件流式同步、同大小修改、符号链接过滤、旧副本不覆盖；巡检误重启防护。Go 单元测试、Linux 编译、Compose 配置验证。生产部署必须先提交推送，再服务器拉取、停止旧服务释放端口、启动新镜像并验证。
