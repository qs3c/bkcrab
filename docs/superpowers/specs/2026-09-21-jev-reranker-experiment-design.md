# Jev 与 Qwen3 重排对照实验

日期：2026-09-21。目标：交付同一批问题的效果与延迟实测对比，给出是否适合替换默认 reranker 的建议。

## 当前状态

- 用户已授权推进实验；服务器恢复后已开始实现、预检与数据冻结。
- 本地源码检查基线：`549971d`；工作区在实验准备前无未提交改动。
- 初次连接因服务器挂起失败；用户恢复服务器并完成 Tailscale 身份验证后，SSH 已接通。
- 服务器运行源码基线 `549971d`，50 题英文数据的 generation 为 READY、12829 chunks；Qwen3 实际为 2 threads、2 parallel slots、Q4_K_M，1600MiB 内存上限。
- OpenRouter 已通过带鉴权的公开文本探针，HTTP 200，返回 `typesafe/jev-1.13-20260917` 和 usage/cost；本地探针不计正式延迟。密钥不进入本文、仓库或实验工件。
- 固定回答模型为现有系统绑定 `opencode-go/deepseek-v4-flash`。回答和 judge 使用现有订阅，真实美元单价不可由配置中的占位价格推断；报告 token 用量。
- 2026-09-09 结果仅作历史背景：Qwen3 重排平均约 47 秒；当时 case concurrency=2。这不是本次并发为 1 的基线。

## 已确认的实现约束

1. `internal/rag/rerank/rerank.go` 已有统一接口，返回候选的原始 index 和 0～1 score。
2. `qwen3.go` 逐候选调用 llama.cpp `/completion`，仅预测一个 token，并使用全局并发槽。应复用该客户端，避免另写一个不同的 Qwen3 基线。
3. `deploy/docker/docker-compose.models.yml` 默认配置为两个线程、一个并发槽、Q4_K_M 权重。实际服务配置必须恢复连接后读取验证，不能拿模板当实际配置。
4. `search.go` 使用 SearchContent 打分，但回答使用 AnswerText；冻结数据必须同时保存两者，不得把额外检索增强文本误当作原始答案证据。
5. 当前 reranker 和 trace 只保留 TopN；旧 Top5 导出不能还原完整 Top20。本次必须新采集召回候选和所有重排分数。
6. `Service.Execute` 复用生产的 SearchEvaluationWithOptions、GenerateAnswer；实验的完整回答应复用这些组件。
7. 当前评测使用 Service 的全局 reranker。仅修改 Profile.rerankerModel 或 timeout 字段不保证切换实际客户端。每组必须记录并核实实际绑定。
8. 当前文档级 gold 标签不能当作 chunk 级相关性标签；已有文档命中接近饱和，不能单凭它判断替换效果。

## 实验组与控制变量

正式主对照固定为三组：

| 组 | 重排 | 最终上下文 |
| --- | --- | --- |
| A | 当前服务器上的 Qwen3-Reranker-0.6B，实际权重与参数保持一致 | Top5 |
| B | Jev，逐查询/候选对的 Noul 相关性分数 | Top5 |
| C | 不重排，保留冻结的混合召回顺序 | Top5 |

三组使用同一候选池，每题最多 Top20；不补入未召回的 gold，不为任何组单独重新召回。
主实验关闭 rewrite/HyDE，避免 Planner 随机性混入重排比较；多轮题以冻结的独立查询进行隔离评估，其与线上 Planner 的联合效果只能作为另一个实验。
固定索引、分块、embedding、候选顺序、查询、回答模型及版本、回答提示词、temperature、maxTokens、judge 和指标版本。
正式结果中分别报告英文、中文、无答案、困难样例，不只给混合均值。

## 数据集与校准隔离

- 英文主集：优先复用仓库记录的 Open RAGBench/arxiv 50 题、200 文档及其 READY generation；连接后检查是否仍存在、合同是否一致。失效时从相同公开源、seed=42 重建，并记录新指纹，不声称复用旧索引。
- 中文主集：补充 50 题，使用可外发的公开中文资料；包括直接证据、主题近似干扰、否定/条件、多证据和无答案问题。明确标注来源和人工/模型合成属性。公开中文集只能代表该集，不能替代真实业务验证。
- 另设 10～20 题 pilot/校准集。按来源文档或问题族隔离，校准题不进入正式测试；如需调整提示词或 batching，先结束 pilot 再冻结。
- 无答案题至少覆盖中文主集的 10 题。区分语料本就没有答案、召回遗漏答案、阈值误删答案。
- 保留 reference answer、reference documents；对需要 chunk 指标的子集额外确认精确 context IDs。缺少标签的指标记 missing，不自动推断。
- 中文标签须独立于 Jev/Qwen3 的输出建立；模型辅助标注注明 judge 身份，盲评排序，避免让 Jev 给自己打分。
- 提示词只看到查询、候选文本和必要来源字段，不看到参考答案或相关性标签。

### 服务器恢复后的执行细化

英文主集严格使用真实冻结召回，不补 gold。中文采用 CMRC2018 官方 dev（提交 `c0eb1b6ba219847457e6af3180da722bbeb656af`）的独立组件诊断：40 题将已标注 gold 段落置于候选第 6～20 位，其他候选按字符二元组 BM25 选择；10 题移除 gold 及包含标注答案的段落。另有 10 题按来源段落隔离的校准集。中文原始顺序只是构造的弱召回，不是 bkcrab 的 RRF；结果必须与英文分开，不声称是中文真实检索或经人工认证的不可回答题。本轮未覆盖的多证据、条件否定、业务语料与真实在线端到端计时须列为限制，不能用组件成绩冒充。

## Jev 评分与调用策略

初始问题语义：候选是否提供有助于回答查询的具体证据；仅主题相似不够；支持子问题和纠正错误前提的证据也可相关。
`noul` 的输出作为相关性排序分数，不使用 `confidence` 作为排序分数。

Pilot 比较以下方式，正式只保留预先选定的一种：

- 单候选一个请求，连接复用，最多 4 个请求并发；作为隔离质量基线。
- 最多 5 个候选一批，每个候选一个明确指向自身文本的问题，最多 2 批并发；考察减少网络往返是否引入干扰。

不预设大批量一定更快或质量不变。遵守所选渠道的实际上下文及速率限制，超过输入预算按候选边界拆批；不静默截掉可能含证据的尾部文本。
本轮采用 OpenRouter Decisions API：`POST https://openrouter.ai/api/alpha/decisions`，初始 model=`typesafe/jev-1.13`；恢复执行时用公开样例核实协议和实际返回 model ID。它是 alpha 接口，如协议变化先更新预检与适配，不能直接换成 chat/completions。
正式冻结 provider、请求协议、实际 model ID、prompt hash、批大小、并发、超时和重试配置。
首次主评分不自动重试；错误计入错误率。恢复性重试另记 attempt 和累计耗时，不覆盖首次失败。

## 分开衡量排序与过滤

第一层主对照：A/B/C 都不做分数过滤，纯 Top5，隔离重排效果。
第二层对照：A 使用现有 0.5 阈值；B 使用仅在校准集选定的阈值；C 无可比模型概率阈值。
同为 0～1 不代表阈值可互换。所有候选原始分数保存下来，校准重放不产生新推理费用。
默认阈值选择规则：在校准集有答案题证据保留率不低于 Qwen3/0.5 的候选阈值中，最大化无答案题的正确空上下文比例；并列取较低阈值。无法满足则正式标注过滤方案不合格，不在测试集继续调参。

## 效果指标

主指标：Context Precision、Context Recall、最终答案 Factual Correctness。
辅助指标：Faithfulness、Response Relevancy、引用指标、无答案题的拒答/幻觉回答比例；有可靠 chunk gold 时计算 nDCG@5、Recall@5、MRR。
有答案题的证据丢失率与空上下文率单独报告。文档级与 chunk 级结果分栏。

同题配对比较，每项显示有效分母、缺失数、失败数和原始均值；失败不当 0，也不从可用性统计中消失。
按来源文档/对话分组做 10,000 次配对 bootstrap，给出 95% 区间；不同采样重复不能当成独立问题增加样本量。
报告至少 5 个退化案例及其候选、排序、证据和答案；不足 5 个则列出全部。

## 延迟指标

所有正式请求从 `100.93.173.10` 发起，Python/Go 本地工作站调用时间不能代替服务器结果。

1. 重排阶段：候选准备完毕到拿到完整分数并排序，包括连接、传输、等待和解码。
2. 用户链路：检索开始到答案首 token（可准确采集时）和答案完成；不含 judge。
3. 可用性：超时、429、其它错误、重试、回退比例；成功请求延迟和全请求完成/失败延迟分别报告。

正式单查询实验 case concurrency=1，先固定 5 次预热并另存。随后按题随机交错 A/B/C，固定种子，重排测试 3 轮，报告 mean/P50/P95、样本数及配对差值；本地 Qwen3 保持线上原有 slots 配置。
重复请求不走本地结果缓存；模型前缀缓存保持实际服务设置并记录。冷启动单列，不混入稳态分位数。
查询并发=2 的小规模压力对照使用固定 20 题、另表报告，不与并发=1 的时延混算。
完整回答每题每组至少 1 次真实生成；不能用旧回答或不同 query 的均值相减伪造端到端时延。
若只做到冻结候选回放，结果必须标为“重排＋回答回放”，不得标成实时完整 RAG 链路。

## 验收与结论边界

本轮候选目标（实验判定标准，不是既有性能事实）：

- Jev 重排 P95 比本次 Qwen3 基线降低至少 80%，且单查询模式 P95 不超过 5 秒。
- 中文和英文分别检查主质量指标。探索性非劣界值设为 0～1 指标下降 0.03；配对差值的 95% 区间下界高于 -0.03 才可对该指标支持非劣结论。
- 小样本区间跨越非劣界值时结论为“证据不足”，不能用不显著来断言质量相同。
- 不能以大量超时回退 RRF 后的快响应宣称 Jev 快；模型成功率与降级后的服务成功率分开。
- 无答案和严重错排单独审查；即使平均指标合格也要解释严重退化。
- 未满足全部证据条件时可推荐继续实验或按场景使用，不能自动切换生产默认配置。

## 成本、状态与运行边界

- 只使用公开评测材料，首轮不外发私人知识库。密钥仅从环境/现有服务端配置读取，不提交到仓库，不写进结果和日志。
- 首轮 Jev 预算硬上限为 $5 估算推理费用；每次发起前按待发送输入上限预留费用，计入重试。遇到费用未知先记录 token，未核实价格前不开展全量付费测试。
- 回答与 judge 费用另计，不能包含在 Jev 的低成本宣传中。先做 5 题三组 smoke，核实价格或订阅配额及 token 后，在 manifest 写入首轮明确上限，再开始正式全量；用户无需重复授权普通实验调用，但不能购买充值或套餐。
- 原始记录追加写入，具备 case/arm/repeat/attempt 标识；重启只补缺失工作，不覆盖已完成记录。连续 3 个认证/余额错误停止远端组，保留其它可完成准备。
- 初期使用独立 Docker 实验工具复用 bkcrab 模块，尽量不替换线上网关。若必须部署代码：先本地提交推送，服务器拉取；保留实际 Compose overlays；停止旧 bkcrab 释放端口后再启动新容器，避免误停数据库和模型服务。
